# AI护心镜 —— 全龄心电风险与医患协同平台 · 部署指南

本指南介绍如何在本地开发与生产环境部署「AI护心镜」平台。系统由两部分组成：

- **后端**：FastAPI + Uvicorn + SQLAlchemy 2.0 + SQLite（可切 PostgreSQL），位于 `backend/`。
- **前端**：React 19 + Vite + TypeScript + Tailwind，位于 `frontend/`，构建后可由后端同源托管，也可由 Nginx 单独托管。

算法层 `src/`、模型 `models/`、知识库 `knowledge/`、上传目录 `uploads/`、存储目录 `storage/` 均在项目根，后端运行时直接复用，无需改动。

> 旧版 Streamlit 单体应用的部署说明已归档至 `docs/部署指南_Streamlit旧版.md`，本文档仅针对重构后的前后端分离版本。

## 1. 环境要求

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| Python | 3.10 ～ 3.11（推荐 3.11） | 深度学习与算法依赖对版本较敏感，勿用 3.13 |
| Node.js | ≥ 18（推荐 20/22 LTS） | 构建前端 |
| npm | ≥ 9 | 随 Node 安装 |
| 操作系统 | Windows 10/11、Linux（Ubuntu 20.04+）、macOS | 提供 `start.bat` / `start.sh` |

> 心电分析会加载 XGBoost 与 CNN(keras/tensorflow) 模型，首次启动后端约需 30～60 秒，属正常现象。

## 3. 环境变量配置

复制示例文件并按需修改：

- Windows：`copy backend\.env.example backend\.env`
- Linux/macOS：`cp backend/.env.example backend/.env`

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `SECRET_KEY` | 生产必填 | dev 占位串 | JWT 签名密钥，**生产必须改成随机长字符串** |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 否 | `720` | 访问令牌有效期（分钟） |
| `DATABASE_URL` | 否 | `sqlite:///<项目根>/storage/ecg_web.db` | 数据库连接串；PostgreSQL 示例见下 |
| `CORS_ORIGINS` | 否 | 本地 5173 | 允许的前端来源，逗号分隔；同源托管时可忽略 |
| `ZHIPU_API_KEY` | 否 | 空 | 智谱 GLM 密钥；留空时 AI 接口返回「未配置」，其余功能正常 |
| `FRONTEND_DIST` | 否 | `<项目根>/frontend/dist` | 前端产物目录，需异地部署时设为绝对路径 |
| `SERVE_FRONTEND` | 否 | `true` | 是否由后端托管前端；纯 API/Nginx 托管时可设 `false` |

> 密钥只通过环境变量注入，不要写入代码或提交到仓库。

### 切换 PostgreSQL（可选）

```
DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/ecg
```

并 `pip install "psycopg[binary]"`。表结构在后端首次启动时自动创建（`init_db()`）。

## 4. 本地开发部署

开发模式下后端提供 API，前端由 Vite 提供热更新，`/api` 请求自动代理到后端。

### 4.1 准备后端依赖

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux/macOS
source .venv/bin/activate

pip install -r backend/requirements.txt
```

### 4.2 一键启动（推荐）

- Windows：`start.bat dev`
- Linux/macOS：`./start.sh dev`

脚本会分别拉起后端（Uvicorn `--reload`，端口 8000）与前端（Vite，默认 5173）。浏览器打开 Vite 输出的地址（默认 <http://localhost:5173>）。

### 4.3 手动启动（分步）

终端 1（后端）：

```bash
cd backend
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

终端 2（前端）：

```bash
cd frontend
npm install
npm run dev
```

可用的后端地址：

- API 文档（Swagger）：<http://127.0.0.1:8000/docs>
- 健康检查：<http://127.0.0.1:8000/api/v1/health>

## 5. 生产环境部署

### 5.1 方式 A：后端同源托管（最简单，单机推荐）

前端构建为静态文件，由 FastAPI 一并提供，**只暴露一个端口**。

一键完成（构建 + 启动）：

- Windows：`start.bat`（或 `start.bat prod`）
- Linux/macOS：`./start.sh`（或 `./start.sh prod`）

脚本逻辑：若 `frontend/dist/index.html` 不存在会先自动执行前端构建，然后启动 Uvicorn 托管前端与 API。

访问入口：<http://127.0.0.1:8000/>

等价的手动步骤：

```bash
# 1) 构建前端（自托管模式，产物在 frontend/dist，资源用相对路径）
cd frontend
npm ci            # 或 npm install
npm run build:local

# 2) 启动后端（自动挂载 frontend/dist）
cd ../backend
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

说明：

- 后端对非文件路径（如 `/patient/reports/123`、`/sos`）做了 **SPA 回退**，直接访问或刷新前端深层路由不会 404；`/api`、`/docs` 等后端路由优先匹配；找不到的 `.js/.css` 等仍正确返回 404。
- 只想提供 API、不托管前端时，在 `.env` 设 `SERVE_FRONTEND=false`。

### 5.2 方式 B：Nginx 托管前端 + 反代后端（推荐用于公网/多实例）

1. 构建前端：`cd frontend && npm run build:local`
2. 后端仅跑 API：`SERVE_FRONTEND=false uvicorn app.main:app --host 127.0.0.1 --port 8000`（建议配合 systemd / 进程守护）
3. 复制 `deploy/nginx.conf.example` 到 Nginx 配置目录，把 `root` 改为 `frontend/dist` 的绝对路径、`server_name` 改为域名/IP，`/api/` 反代到 `127.0.0.1:8000`，然后重载 Nginx。

Nginx 已处理静态资源缓存与 SPA `try_files ... /index.html` 回退。

### 5.3 后台常驻与开机自启（Linux，可选）

可用 systemd 管理后端，示例服务（保存为 `/etc/systemd/system/ecg.service`）：

```ini
[Unit]
Description=AI HuXinJing ECG Backend
After=network.target

[Service]
WorkingDirectory=/opt/ECG-Auxiliary-Screening/backend
ExecStart=/opt/ECG-Auxiliary-Screening/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
EnvironmentFile=/opt/ECG-Auxiliary-Screening/backend/.env

[Install]
WantedBy=multi-user.target
```

启用：`systemctl daemon-reload && systemctl enable --now ecg`，日志：`journalctl -u ecg -f`。

## 6. 构建说明（两种前端构建模式）

| 命令 | 用途 | 产物 |
| --- | --- | --- |
| `npm run build` | 妙搭托管链路（默认） | `frontend/dist/output`、`dist/output_resource`（CDN 分层） |
| `npm run build:local` | 本地/自托管/单机部署 | 标准单目录 `frontend/dist`（index.html + assets，相对路径） |

**自部署请使用 `npm run build:local`**，这样 FastAPI 或 Nginx 才能在同一目录直接托管。当前自托管产物体积：JS ≈ 6.5MB（gzip ≈ 2.0MB）、CSS ≈ 137KB（gzip ≈ 21KB），体积主要来自 Plotly.js 与 ECharts，属正常；如后续追求首屏速度可做路由级代码分割。

## 7. 一键启动脚本参考

| 命令 | Windows | Linux/macOS | 作用 |
| --- | --- | --- | --- |
| 生产启动 | `start.bat` / `start.bat prod` | `./start.sh` / `./start.sh prod` | 缺产物先构建，再由后端托管前端 |
| 开发启动 | `start.bat dev` | `./start.sh dev` | 后端热更新 + 前端 Vite |
| 仅构建前端 | `start.bat build` | `./start.sh build` | 生成 `frontend/dist` 后退出 |

可覆盖环境变量：`PYTHON`（解释器）、`HOST`（默认 127.0.0.1）、`PORT`（默认 8000）。

示例（指定 Python 与端口）：

```bat
set PYTHON=D:\Python3.11.9\python.exe
set PORT=8012
start.bat
```

```bash
PYTHON=/usr/bin/python3.11 HOST=0.0.0.0 PORT=8000 ./start.sh
```

> Windows 脚本使用纯英文提示以规避批处理代码页问题；首次运行若检测不到后端依赖会自动 `pip install`，前端缺 `node_modules` 会自动 `npm install`。Linux 下若提示权限不足，先执行 `chmod +x start.sh`。

## 8. 部署后自检清单

1. 健康检查：`GET /api/v1/health` 返回 `{"status":"ok",...}`。
2. 浏览器打开站点根地址，出现登录页（同源托管时为后端端口，Nginx 时为 80/443）。
3. 直接刷新某个前端深层路由（如 `/sos`、`/doctor/ecg`）页面正常、不 404。
4. 注册/登录医生账号 → 建档 → 上传 `csv/txt/dat` 心电文件 → 能得到双通路风险结果（首次分析需加载模型，请稍候）。
5. TXT/PDF 报告可下载；SHAP 图表可显示（样本不足时优雅降级）。
6. 配置了 `ZHIPU_API_KEY` 时 AI 解读可用；未配置时 AI 接口给出未配置提示，不影响其余功能。

## 9. 常见问题（FAQ）

**Q1：浏览器打开是白屏 / 资源 404？**
确认用的是 `npm run build:local`（产物为标准 `dist/`、相对路径），而不是妙搭分层的 `npm run build`；并确认访问 `/` 返回的是 HTML（前端页面）而非 JSON。

**Q2：后端启动报 `ModuleNotFoundError`（tensorflow / xgboost 等）？**
Python 版本不符或依赖未装。请用 Python 3.10～3.11 创建虚拟环境后执行 `pip install -r backend/requirements.txt`。

**Q3：后端启动很慢？**
首次需加载 XGBoost 与 CNN 模型，约 30～60 秒；等待 `/api/v1/health` 返回 `ok` 即可。

**Q4：心电分析一直转圈 / 超时？**
确认 `models/` 下三个模型文件存在、`uploads/` 可写；Nginx 反代时已将 `proxy_read_timeout` 放宽到 180s、`client_max_body_size` 设为 50m。

**Q5：AI 接口提示未配置？**
未设置 `ZHIPU_API_KEY`。在 `backend/.env` 填入智谱密钥后重启后端；不配置也不影响筛查、报告、康养等核心功能。

**Q6：端口被占用（8000 已在运行）？**
用 `set PORT=8012` 后再 `start.bat`（Linux：`PORT=8012 ./start.sh`）换端口，或先停掉占用进程。

**Q7：数据库文件在哪？如何备份/重置？**
默认在 `storage/ecg_web.db`。备份直接复制该文件；重置请在服务停止后删除它，重启会自动重建空表（已有数据会丢失，请先备份）。

**Q8：紧急呼救是系统自动拨号吗？**
不是。患者端「一键呼救」通过 `tel:` 链接唤起本机拨号盘，由用户本人确认拨打，系统不代拨；未登录时以浏览器 `device_key` 标识本地紧急联系人。

## 10. 数据安全与合规提醒

- 平台为 **AI 辅助筛查工具，结果不构成诊断结论**，临床决策须由医生结合病史与检查作出。
- 生产环境务必修改 `SECRET_KEY`、使用强口令、按需开放端口，并建议在 HTTPS 反向代理之后对外提供服务。
- 心电数据与患者档案属个人健康信息，请按当地法律法规做好访问控制、加密传输（HTTPS）与定期备份。
